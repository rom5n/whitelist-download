# Project Overview
Whitelist-download is an automatic VLESS config aggregator and local subscription server. It downloads free VLESS configs from GitHub sources, de-duplicates them, checks that they work, tags them with a country (GeoIP), and serves them as one subscription link from a local HTTP server. A React dashboard is embedded in the Go binary for monitoring and management. The app runs as a system-tray application on Windows, Linux and macOS. Tech stack: Go (backend, single module at the repo root) and React + TypeScript + Vite + Tailwind CSS v4 (frontend).

# Developer Commands
* **Frontend** (`cd frontend`): `yarn dev` (Vite; proxies `/api` and `/sub` to `localhost:55000`, so run the backend too), `yarn build` (`tsc -b && vite build`, **outputs to `backend/http/dist`**), `yarn lint`, `yarn preview`.
* **Backend** (`cd backend`; `go.mod` lives in the repo root, not in `backend/`):
    * `go run main.go` — run locally. `backend/http/dist` must exist (see "Embedded frontend"), otherwise compilation fails.
    * `go build ./...` and `go vet ./...` — the check to run after any Go change. `go test ./...` runs the unit tests (`aggregator`, `config`, `http/handler`, `tray`); the sing-box dependency makes the first compile slow. Add `-race` (needs CGO/gcc) after touching concurrency code. Tests that touch `config.Save` must call `testenv.Isolate(t)` so they never write to the developer's real `config.json`.
    * Windows release build: `go build -tags with_utls -ldflags "-H=windowsgui -s -w -X main.version=<x.y.z>" -o wl-download.exe main.go`
    * Linux/macOS release build: same without `-H=windowsgui`; requires `CGO_ENABLED=1` (systray) plus `libgtk-3-dev libayatana-appindicator3-dev gcc` on Linux. Windows builds use `CGO_ENABLED=0`.
    * `-tags with_utls` is required by CI for sing-box uTLS/Reality; keep it in every release build.
* **Docker:** `docker compose up --build` (multi-stage: builds frontend into `backend/http/dist`, then a static backend with `-tags "with_utls headless"` and `CGO_ENABLED=0`, mounts `./data`; uses `XDG_*` env vars to redirect config/data/logs). `headless` swaps the tray for `run_headless.go` (the systray needs cgo and a desktop); `run_tray.go` is the default. Pass the version with `--build-arg VERSION=x.y.z`.

# Architecture & Directory Structure
Go module: `github.com/rom5n/whitelist-download`. Entry point `backend/main.go`.

* `backend/main.go` — startup order: `logging.Initialize` → `config.Load` → `startup.Add` → build shared state (`SafeConfigsCache`, `Statistics`, `SafeUpdaterState`, GeoIP `Locator`) → `tray.Run(startApp)`. `startApp` launches the aggregator, opens the browser, starts the updater and the HTTP server, then waits on a `sync.WaitGroup`. SIGINT/SIGTERM cancel the shared `context`. `version` is injected via `-X main.version=...` and passed to the updater through `ctx.Value("version")`. Note: `main` begins with `time.Sleep(10s)` (autostart delay) — account for it when testing startup.
* `backend/aggregator` — `StartPollingConfigs` → `runPollingLoop` (testable with a fake update; re-reads config every cycle; the next update is due `UpdateInterval` minutes after the previous one, so pause/resume and interval changes reschedule it; retries in 30s on failure; sleeps while updates are paused; an update interrupted by shutdown is not reported) and `UpdateConfigs` pipeline: `getConfigs` (fetch sources, drop duplicates ignoring the `#fragment`, only `vless://`) → `filterWorkingConfigs` (parallel, up to `maxWorkers=150`) → `formatConfigs` (GeoIP, rewrites the fragment to `<flag> <Country> — #<n>`) → `SortConfigs` (group by country) → `updateCacheAndFile` (sets cache, writes `configs.txt` atomically via `.tmp` + rename). Whole update has a 5-minute timeout.
    * `Scheduler` (`scheduler.go`) — single owner of the auto-update controls, shared by the polling loop, the HTTP API and the tray: `State`, `PauseFor`, `PauseForever`, `Resume`, `SetWorkingCheckLevel`, `SetUpdateInterval` (also updates `Statistics`), `Reschedule`. It also collects update outcomes: the loop and the manual-update handler call `ReportUpdate(UpdateEvent{Manual, Result, Err})`; `LastError()` and `Subscribe(callback)` (synchronous, must not block; subscribe before updates start) expose them — the tray uses them for the error icon and notifications. State is persisted in `config.json` (`paused_until`: `0` active, `-1` = `config.PausedForever`, `>0` Unix time of resume); pause changes wake the loop through a buffered channel, so resuming updates immediately. The level applies from the next update. A manual update (`/api/update-configs`, tray "Обновить сейчас") works while paused. `UpdateInProgress()` tells whether any update is running.
    * Working check: `WorkingCheckLevel` (`config.WorkingCheckPing` = 1, `config.WorkingCheckSingBox` = 2) 1 = TCP dial to host:port (2s); 2 = real sing-box instance with a local SOCKS inbound on ports `20000+i` (pool of `maxWorkers`), requesting `http://cp.cloudflare.com/generate_204` through it (7s). `buildSingBoxOptions` supports only VLESS with `tls`/`reality` security and `ws`/`grpc` transports — extend it there when adding transports.
* `backend/http` — `http.go` builds the `ServeMux` and server on `0.0.0.0:<cfg.Port>` (default 55000); embeds the frontend with `//go:embed dist/*`. `backend/http/handler` holds handlers (closures returned by constructors that receive shared state):
    * `subscription.go` — `<SubscriptionPath>` and `<SubscriptionPath>/...` (default `/sub`): base64 body + `profile-title`/`announce`/etc. headers. Path forms: `/sub/50` (limit), `/sub/10-30` (offset-limit), `/sub/<country>` and `/sub/<country>/10-30` (country with `-` for spaces, e.g. `united-states`). Serves from cache, falls back to the file.
    * `api_configs.go` — `GET /api/configs?country=&offset=&limit=` (offset is 1-based).
    * `api_info.go` — `/api/subscription-link`, `/api/statistics`, `/api/get-config`, `/api/set-config` (validates, saves, replies with the restart state; checks for an app update only when the auto-update policy changed, because it is called on every keystroke pause), `GET /api/restart-required`.
    * `api_polling.go` — auto-update controls: `GET /api/polling`, `POST /api/polling/pause` (`{"minutes":N}` or `{"forever":true}`), `POST /api/polling/resume`, `POST /api/polling/check-level` (`{"level":1|2}`); all return the resulting `domain.PollingState`.
    * `api_system.go` — `/api/update-configs` (forced update; also triggered from the tray via GET), `/api/logs`, `/api/restart`, `/api/updater/status`, `POST /api/updater/download`.
    * `web.go` — serves the SPA with fallback to `index.html`. `helpers.go` — URL param parsing and `configsFilePath`.
    * Any new/changed endpoint must be reflected in `frontend/API_DOCUMENTATION.md` and `frontend/src/api.ts`.
* `backend/config` — `Config` struct (JSON tags = `config.json` keys), `Load/Save/Set`, dedicated setters `SetWorkingCheckLevel` / `SetPausedUntil` / `SetUpdateInterval` / `SetAutoStart` / `SetNotifications` / `SetLanguage` (validate, persist via `setAndSave`, roll back on save failure), and `RetrieveSafe(fields ...Field)`, which returns a **copy** containing only the requested fields under the read lock. New setting = add the struct field + `Field` constant + `Set` + `RetrieveSafe` case (+ default in `newDefaultConfig`, + frontend settings UI). `Config.Set` (used by `/api/set-config`) intentionally does **not** copy the tray-managed fields (`PausedUntil`, `AutoStart`, `Notifications`, `Language`), so a stale settings form can't change them; new tray-managed settings must follow the same rule. `config.Validate` (`validate.go`) checks everything the dashboard sends — the dashboard saves on every change, so an incomplete value (empty port, path without `/`) must never reach `config.json`; keep it in sync with `frontend/src/validateConfig.ts`. Settings that only take effect after a restart (`app_name`, `port`, `subscription_path`) are tracked by `MarkStarted()` (called in `Load`) and `PendingRestart()`; add a setting there if it is read only at startup.
* `backend/domain` — thread-safe shared types: `SafeConfigsCache` (country → configs; `Get/Set` clone the map), `Statistics` (embedded RWMutex; use `Summary()`, `AppVersion()`, `SetUpdateInterval()` instead of touching fields), `PollingState` (JSON of the auto-update controls), `SafeUpdaterState` (status: `checking|available|downloading|installing|up-to-date|error`), `SafeFile`.
* `backend/geo_ip` — `Locator` with an embedded `geoip.mmdb` (`go:embed`); resolves host via DNS, returns country name + emoji flag, or `Unknown`/`❓`.
* `backend/updater` — self-update from GitHub Releases of `rom5n/whitelist-download` (checks every 15 min). Downloads the asset named `wl-download-<GOOS>[-<GOARCH> on darwin][.exe on windows]` — this name is coupled to `.github/workflows/release.yml`; change both together. Replaces the running exe (old one renamed to `<exe>.old`, removed on next start in `setExecutableDir`) and restarts. Auto-update is gated by `AutoUpdateMajor` / `AutoUpdatePatch`; versions are compared on `major.minor[.patch]` (minor bump counts as "major").
* `backend/startup` — per-OS autostart via build-tagged files by filename suffix: `_windows` (registry `HKCU\...\Run`), `_linux` (`~/.config/autostart/*.desktop`), `_darwin` (`~/Library/LaunchAgents/*.plist`). All expose `Add(cfg)` and `Remove(cfg)`; `startup.Apply(cfg)` picks one according to `Config.AutoStart` (called on start and when the tray toggle changes).
* `backend/desktop` — desktop integration without third-party libraries: `CopyToClipboard` (clip.exe / pbcopy / wl-copy, xclip, xsel), `Reveal` (explorer `/select,` / `open -R` / xdg-open), `Notify` (Windows toast through PowerShell with the title/message passed via environment variables and an AppUserModelID registered in HKCU, `osascript`, `notify-send`). Helper processes run without a console window on Windows (`hideWindow`). Never build shell commands by concatenating user data.
* `backend/tray` — system tray (`getlantern/systray`); `tray.Run` blocks the main thread. Files: `tray.go` (state, 1s refresh loop that redraws only what changed, so dashboard changes show up in the tray), `menu.go` (menu structure and bindings), `actions.go` (click handlers), `notify.go` (desktop notifications), `format.go` (`snapshot` = everything the menu shows, rendered by pure, unit-tested functions), `lang.go` (RU/EN catalog: every user-visible string is a `text{en, ru}`; add both), `lang_windows.go` / `lang_unix.go` (system language detection), `icon.go` (icons; `dimPNG` for paused, `badgePNG` red dot for error, `transformICO` applies them to every frame of the .ico).
    * Menu: status line; open dashboard; copy subscription link (asks the local `/api/subscription-link`); update now; "Auto-update" (pause 1h/4h/24h/forever, resume); "Update interval" presets; "Configs check" (ping/sing-box); "Preferences" (start with the system, notifications, language auto/ru/en); "Files" (config.json, configs file, log); app self-update item (check / update to vX / progress / retry, driven by `SafeUpdaterState`); quit.
    * Language: `Config.Language` (`auto` follows the OS). All titles are (re)set in `refresh`, so a language change applies within a second. Notifications: failures are reported when they start (not on every 30s retry), recovery and user-triggered updates are always reported, plus "new app version available" once per version; disabled by `Config.Notifications`.
    * Native look (`theme_windows.go`; no-op `theme_unix.go`, macOS/GTK menus already follow the system): the Win32 popup menu follows the system light/dark app theme through the undocumented uxtheme ordinals (`SetPreferredAppMode` 135, `FlushMenuThemes` 136, …), re-applied when `AppsUseLightTheme` changes (`RegNotifyChangeKeyValue`, no restart); on Windows 11 a WinEvent hook gives menu windows the regular corner radius (`DWMWCP_ROUND`) — it must be re-applied on show, the system resets it. Started from `onReady` (`watchNativeLook`).
    * Rules: create menu items only in `buildMenu`; `refresh` owns the cached titles and must run only on the refresh goroutine; after any click the checkbox states are force re-applied (on Linux a click toggles a checkbox natively); tray strings live in `lang.go`, not inline; the tray talks to `aggregator.Scheduler` and `Config` setters directly and to the local HTTP API only for "update now" and the subscription link.
* `backend/paths` — `ResolveDataFile` / `MigrateLegacy`: XDG data-file resolution and one-time migration of legacy files from the exe directory; `ConfigsFile` / `ConfigsFileName` for the configs file; `RenameDataFile` (used by `config.Load` to migrate the removed `configs_path` setting). Must not import other project packages (`logging` depends on it); callers log the returned errors. Use it instead of re-implementing path logic.
* `backend/logging` — global `logging.Log` (zap JSON, debug level) writing to a size-rotated file (25 MB); `logging.LogPath` is served by `/api/logs`. The log file is **truncated on every start**.
* `frontend/src` — React app (`api.ts` API client, `components/`, `i18n.tsx` — Russian by default, `ThemeContext.tsx`, `countryFlags.ts` — country name → flag emoji → ISO code, `usePollingState.ts` — polls `/api/polling` every 3s so tray changes appear in the UI, `formatTime.ts`). `App.tsx` polls `/api/statistics` every 10s; when `last_update` changes it refetches the configs already shown in place. The selected config is kept by its link (without the `#name`), not by its index, so a refresh keeps the selection, the scroll position and the focus.
* Header attention dot: `NavTabs` shows a dot next to a section (`Attention` in `navigation.ts`): `busy` (accent, sends out rings) while settings save, configs update or the server restarts; `action` (warning) when settings are invalid/failed, a restart is required or updates are paused. `SettingsView` reports its activity through `onActivityChange`. The paused pill in the header resumes updates on click.
* Settings screen: `SaveStatus.tsx` — one fixed-width slot for saved / saving / invalid / error / "restart required" (all states stacked in one grid cell, cross-faded), no blocks appear under the header; `RestartVignette.tsx` — the restart glow is portaled to `<body>` (fixed, full window, no radius, `pointer-events: none`, above everything); `IntervalField.tsx` — text input + presets; `ImportConfigs.tsx` — downloads a `.txt` of configs by country/count/offset through `/api/configs` (offset in the UI is "skip N", the API offset is 1-based). Settings are saved automatically — there is no Save button: `useAutoSaveConfig.ts` sends every change (text fields after a 600ms typing pause, toggles and the sources list at once), never sends values that fail `validateConfig.ts`, serializes requests, flushes on unmount/page hide, and reports the restart state from each save; `/api/restart-required` itself is polled every 3s by `useRestartState` in `App`: while a restart is pending `SettingsView` shows the orange window vignette, "restart required" in the status slot and a breathing restart button (`breathe` utility, opacity only). Working check level and pause are applied immediately via `/api/polling/*` (`components/AutoUpdateControl.tsx`, level switch in `SettingsView`) and are not part of the auto-saved fields.
* Frontend UI layer:
    * `src/index.css` — design tokens. Theme values are plain variables per theme (`.dark` / `.light`: `--bg`, `--surface`, `--raised`, `--sunken`, `--line`, `--fg`, `--fg-2`, `--fg-3`, `--accent*`, `--success*`/`--warn*`/`--danger*` with `-text` (AA text) and `-soft` (tint) variants, `--elev-*`); `@theme inline` maps them to utilities (`bg-surface`, `text-fg-2`, `border-line`, `bg-accent-soft`, `shadow-sm`, ...). Radii `rounded-sm/md/lg/xl` = 8/12/16/24px (chips / buttons+inputs / cards / panels), `rounded-porthole` = 44px (the QR window). Layout: the header and the sidebar are one surface (`--surface`, no lines between them); the content is a sheet on `--bg` with rounded top corners. `scroll-fade` + `useScrollFade` fade the edges of a scroll area only where content is hidden. Type scale 12/14/16/20/28 (`text-xs/sm/base/xl/3xl`). Motion tokens: `ease-out`, `ease-spring` (a spring sampled into `linear()`), keyframe utilities `animate-enter/fade/pop/shimmer`, `press` (tap feedback), `breathe`. Base styles live in `@layer base` so utilities can override them. One accent: `#0253F7` (the app icon's blue). Never hardcode colors (`gray-*`, `blue-*`, hex) in components — add a token.
    * Fonts are self-hosted (Onest + JetBrains Mono, Latin and Cyrillic subsets only, from `@fontsource-variable/*`); no Google Fonts/CDNs — the dashboard must work offline and in censored networks.
    * Flags are round SVGs from `circle-flags` (`ui/Flag.tsx`, `<Flag emoji>` or `<Flag country>`), never emoji: Windows has no flag emoji, and an emoji-font polyfill failed in Firefox (it detects support with Firefox's own Twemoji font). Each flag is a separate asset (`assetsInlineLimit` in `vite.config.ts` keeps them out of the bundle); an unknown code falls back to the code as text.
    * `src/ui/` — base components: `Select` (select-only combobox with rich options, typeahead, loading state), `Button` (variants primary/secondary/ghost/danger, sizes md 44px / sm with a 44px hit area, `loading`), `IconButton` (44×44, `label` = aria-label + tooltip), `Card`, `Field` (label/hint/error/warning wired with aria-describedby), `Switch` (role=switch), `SegmentedControl` (radiogroup with arrow keys), `Badge`, `Spinner`, `Skeleton`, `EmptyState`, `CopyButton`, `Flag`, `GithubIcon`; input classes in `ui/styles.ts`. Build screens from these; keep every interactive element ≥44px and with a visible focus ring (global `:focus-visible` ring).
    * Motion: CSS first (transform/opacity only). `motion` is loaded lazily through `LazyMotion` (`src/motion/`), use `m.*` (not `motion.*` — `strict` mode throws) and only for exit animations (`AnimatePresence`) and layout/FLIP (`layout`, `layoutId`); presets in `motion/presets.ts`. `MotionConfig reducedMotion="user"` and the `prefers-reduced-motion` block in `index.css` must keep working. Don't animate width/height/top/left, big blurs or `backdrop-filter`.
    * Long lists are virtualized with `@tanstack/react-virtual` (config list in `Sidebar`, `LogsView`); keep rows memoized. `UpdateView` (react-markdown) is lazy-loaded. Polled state is only replaced when it actually changed, so polling doesn't re-render the app.
* `.github/workflows/release.yml` — builds 4 targets on `v*` tags and publishes a GitHub Release. `.agents/skills/` — helper skills for AI agents (Tailwind 4 docs, React best practices, frontend design).

# Runtime Files & Paths
* On start the process `chdir`s to the executable's directory (`setExecutableDir`) and deletes a leftover `<exe>.old`.
* Persistent files live in XDG directories (`github.com/adrg/xdg`; overridable with `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`): `config.json` → `<config>/whitelist-download/`, `configs.txt` (`paths.ConfigsFileName`, not configurable; `paths.ConfigsFile()` resolves it) → `<data>/whitelist-download/`, `app.log` → `<state>/whitelist-download/`.
* Legacy files next to the executable are auto-migrated to the XDG locations on first run via `paths.MigrateLegacy` / `paths.ResolveDataFile`.
* `config.json` is created with defaults if missing; invalid JSON aborts startup (`os.Exit(1)`).
* `configs.txt` format: one `vless://...#<flag> <Country> — #<n>` per line. Country parsing in `SortConfigs`, `sendConfigsFromFile` and `extractConfigsFromFile` relies on the `" — "` separator — do not change the fragment format in one place only.

# Embedded frontend
`backend/http/dist` is git-ignored and produced by `yarn build`. Before `go build`/`go run` from a clean checkout run `cd frontend && yarn install && yarn build`. Never edit files in `dist` by hand.

# Coding Standards & Guidelines
* **Go:**
    * `gofmt` formatting; PascalCase exported, camelCase unexported. Package names are lowercase (existing exception: `geo_ip`); keep packages domain-driven.
    * Strong typing; avoid `interface{}`/`any`. Known legacy exception: `context.WithValue(ctx, "version", ...)` with a string key — do not copy this pattern; prefer explicit parameters or a typed key.
    * Errors: return them wrapped with context (`fmt.Errorf("...: %w", err)`); do not discard them with `_`. Existing code ignores some errors (e.g. `os.Rename`, `os.Remove`, `Write` on response) — don't add new ones; log with `logging.Log` at least. `os.Exit(1)` is used only for unrecoverable startup errors.
    * Logging: `logging.Log` (zap) with structured fields (`zap.String`, `zap.Error`, ...); never `fmt.Print*`/`log.Print*` in app code (the `log` package is used only inside `logging`).
    * Concurrency: shared state goes through `domain.Safe*`, `domain.Statistics` locks, or `Config.RetrieveSafe` — never read `Config` fields directly from other goroutines. In goroutine fan-out loops guard **all** shared writes with the mutex (e.g. `allErrors` in `filterWorkingConfigs`/`formatConfigs` is joined under `mu`).
    * Respect `ctx` cancellation in long-running loops and network calls; new background goroutines must be registered in the `WaitGroup` and stop on `ctx.Done()`.
    * Cross-platform: OS-specific code goes into `_windows.go`/`_linux.go`/`_darwin.go` files, and every OS-specific function needs an implementation for all three. Don't use Windows-only APIs in shared files.
    * Security: the server binds `0.0.0.0` and the API (`set-config`, `restart`, `updater/download`, `logs`) has **no authentication** — don't add endpoints that expose secrets or execute arbitrary commands/paths without discussing it.
* **TypeScript/React:** follow `eslint.config.js`. PascalCase components, camelCase variables/functions. No inline styles — use Tailwind CSS v4 utilities and the design tokens (see "Frontend UI layer" and `.agents/skills/tailwind-4-docs`); inline `style` only for runtime values (virtual list offsets, progress, CSS variables). Strict typing, no `any`; define interfaces for all API responses and component props. Handle API errors in the UI (`try/catch` / `.catch`). UI strings go through `i18n.tsx`. Call the API with relative URLs (works with the Vite proxy and the embedded build; backend port is `55000` by default).
* **Language:** code, comments and commit messages in English; end-user texts are localized (RU/EN in the frontend and in the tray, see `backend/tray/lang.go`).

# Environment & Setup
* Go 1.26.2+ (per `go.mod`), Yarn 1.22.x, Node 22 (CI). `release.yml` reads the Go version from `go.mod`; `Dockerfile` pins `golang:1.26-alpine` — bump it together with the `go` directive.
* Local server strictly on the configured port (default `55000`); the tray "force update" and browser opening use this port.
* The app modifies OS autostart entries on every start (`startup.Add`) — be careful when running it on a dev machine; it registers the current exe path.
* Sing-box (`sagernet/sing-box`) is a heavy dependency; the first `go build` is slow. `backend/test.exe` is a git-ignored local artifact — never commit binaries.

# Git Workflow
* **Commit Messages:** Conventional Commits (`feat: add new proxy source`, `fix: resolve race condition in cache`, `chore: update dependencies`).
* **Branching:** isolated feature/bugfix branches; PRs target `main`.
* **Before a PR:** `cd frontend && yarn lint && yarn build`, then `cd backend && go vet ./... && go build ./...`. If you changed platform-specific or release-related code, sanity-check with `GOOS=linux`/`darwin` where possible (`go vet` with `GOOS` set, CGO permitting).
* **Releases:** pushing a `v*` tag triggers `release.yml`; the tag (without `v`) becomes `main.version`, which the updater compares against GitHub's latest release.
